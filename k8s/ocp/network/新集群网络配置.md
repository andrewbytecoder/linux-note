## nncp 下发
>特别注意 forwarding: true （开启网口转发） 是否NNCP支持，取决于版本信息,不支持的版本通过machineconfig下发

NetworkManager 版本差异导致对 ipv4.forwarding 连接属性的支持不同。

- 在 NetworkManager 1.54 之前，连接配置（connection profile）不支持 ipv4.forwarding 属性。即使 nmstate 尝试通过 nm-settings 设置该字段，NetworkManager 也会忽略或拒绝，导致连接修改时该属性被清除（日志中的 Clearing unsupported）。
- 自NetworkManager 1.54 起，官方增加了对每个设备（per-device）IPv4 转发的支持，允许在连接中设置 ipv4.forwarding，并在激活连接时自动写入对应的内核参数（net.ipv4.conf..forwarding）。

## 网口 开启 IPv4 转发 (forwarding=true)
>网口有2个：m_nad 和 wai_nad

通过MachineConfig下发 配置，使 net.ipv4.conf.m_nad.forwarding = 1 和 net.ipv4.conf.wai_nad.forwarding = 1

以下是同时为 m_nad 和 wai_nad 两个接口开启 IPv4 转发的完整 MachineConfig 配置。

```yaml
apiVersion: machineconfiguration.openshift.io/v1
kind: MachineConfig
metadata:
  name: 99-enable-ip-forwarding-multi
  labels:
    machineconfiguration.openshift.io/role: worker   # 1
spec:
  config:
    ignition:
      version: 3.2.0
    storage:
      files:
      - contents:
          source: data:text/plain;charset=utf-8;base64,bmV0LmlwdjQuY29uZi5tX25hZC5mb3J3YXJkaW5nID0gMQpuZXQuaXB2NC5jb25mLndhaV9uYWQuZm9yd2FyZGluZyA9IDEKbmV0LmlwdjQuY29uZi5uZWlfbmFkLmZvcndhcmRpbmcgPSAxCg==   # 2
          verification: {}
        filesystem: root
        mode: 420                 # 3
        path: /etc/sysctl.d/99-enable-ip-forwarding.conf   # 4
```

配置说明：

1. `machineconfiguration.openshift.io/role: worker`：指定配置应用的节点角色。如果你的节点角色是 `master`，请相应修改。`MachineConfig` 会通过标签匹配对应的 MachineConfigPool。
2. Base64 编码内容：该字符串是以下内容的 Base64 编码：
```bash
net.ipv4.conf.m_nad.forwarding = 1
net.ipv4.conf.wai_nad.forwarding = 1
```

每个参数独占一行。

3. `mode: 420`：文件权限，等同于 Linux 的 `0644`，表示文件所有者可读写，其他用户只读。
4. `path: /etc/sysctl.d/99-enable-ip-forwarding.conf`：配置文件在节点上的存储路径。`/etc/sysctl.d/ `目录下的 `.conf `文件会在系统启动时由 `systemd-sysctl` 服务自动加载。

应用配置：
`oc apply -f 99-enable-ip-forwarding-multi.yaml`
应用后，`Machine Config Operator (MCO)` 会自动将配置分发到所有匹配的节点，并执行滚动更新（排空 Pod、应用配置、重启节点）以使更改生效。

验证配置：
进入节点调试会话检查：

```bash
oc debug node/<node-name>
chroot /host
cat /etc/sysctl.d/99-enable-ip-forwarding.conf
sysctl net.ipv4.conf.m_nad.forwarding
sysctl net.ipv4.conf.wai_nad.forwarding
```
> ⚠️ 重要提醒

缺少 wai_nad 接口的节点在应用此配置时，systemd-sysctl 服务会尝试设置不存在的接口参数，并在日志中产生类似以下的报错：

`cannot stat /proc/sys/net/ipv4/conf/wai_nad/forwarding: No such file or directory`
这是警告性报错，不会导致节点配置失败或节点无法启动，但会在节点日志中留下错误记录。如果希望完全避免这些报错，建议为不同角色的节点分别创建 MachineConfig（例如：有 wai_nad 的节点使用包含两个接口的配置，没有的节点仅使用 m_nad 的配置）。

## BGPPeer 配置
`自定义资源--BGPPeer`
示例代码

```yaml
apiVersion: metallb.io/v1beta2
kind: BGPPeer
metadata:
  name: internal-bgp-peer
  namespace: metallb-system
spec:
  disableMP: false
  dualStackAddressFamily: false
  ebgpMultiHop: true
  myASN: 65581 # 本端AS自治域
  peerASN: 65520 # 对端自治域
  peerAddress: 100.1.1.1 # 对端peer ip

```
### BGPAdvertisement 配置
`自定义资源--BGPAdvertisement`
示例代码

```yaml
apiVersion: metallb.io/v1beta1
kind: BGPAdvertisement
metadata:
  name: internal-addr-pool-advertisement
  namespace: metallb-system
```
