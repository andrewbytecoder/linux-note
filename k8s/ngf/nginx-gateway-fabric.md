


## nginx网关架构


### 控制平面
控制层充当了一个部署组件的角色，本质上是一个使用 controller-runtime 库构建的 Kubernetes 控制器。它通过监控 Gateway API 资源以及其他 Kubernetes 对象，如服务、端点、秘密密钥等，来管理 NGINX 数据平面的资源分配和配置相关事宜。

主要功能：
- 动态配置：当创建一个新的网关资源时，控制面会自动配置一个专用的 NGINX 部署环境，并通过服务来公开该资源
- 配置管理：Kubernetes 和 Gateway API 的资源会被转换为 NGINX 配置，这些配置通过 gRPC 与 NGINX 代理进行通信，然后安全地传输到数据平面 Pod 中。
- 安全通信：默认情况下，gRPC 连接使用在安装过程中生成的自签名证书。此外，该框架还支持与 cert-manager 的集成，从而实现可选的证书管理功能。


### 数据平面
每个 NGINX 数据平面节点可以作为一个独立的 Deployment 或 DaemonSet 来部署，其中包含一个 `nginx` 容器。这个容器中同时运行着 `nginx` 进程和 NGINX 代理程序，而 NGINX 代理程序负责以下任务：
- 应用配置：代理服务器会接收来自控制平面的更新信息，并将其应用于 NGINX 实例中。
- 处理重新加载操作：NGINX Agent 负责协调配置调整并重新加载 NGINX 的相关内容，从而消除了控制层与数据层节点之间需要共享卷或使用 Unix 信号进行通信的需求。



### 网关资源管理
用户可以在同一个集群中同时运行多个网关，这支持网关之间的灵活操作和隔离
- 并发网关：在一个单一的安装环境中，多个网关对象可以同时运行
- 1:1的资源映射：每个网关资源都唯一对应一个特定的数据平面部署，从而明确划分了所有权和运营权限的边界
