大家好，这一节我们做真正的 Kubernetes 双栈。每个 Pod 同时拿到 IPv4 和 IPv6，Service 也可以同时拥有两个 ClusterIP。

双栈不是把 IPv4 包自动翻译成 IPv6，而是两套地址族并存。应用根据 DNS 结果、目标地址和 socket 选择一条路径。

主课程：https://k8snetworking.com/lessons/14-calico-ipv6

Two independent address families

双栈让两套网络同时可用

IPv4

32-bit address family

192.168.2.10

兼容现有系统、设备和运维工具。

+
IPv6

128-bit address family

fd00:10:244:abcd::a

更大地址空间与面向 IPv6 的基础设施。

关键点：同一个对象可以同时有两种地址，但每个连接仍选择一个地址族。失败切换和优先级由应用与系统 resolver 行为决定。
02

双栈的意思是 IPv4 与 IPv6 同时存在。Pod 可以各有一个地址，Service 可以有两个 ClusterIP，DNS 可以同时返回 A 和 AAAA。

一次 TCP 连接不会同时横跨两个地址族。客户端先选目标地址，再建立 IPv4 或 IPv6 连接。

03

双栈最适合渐进迁移。先让基础设施支持两套地址，再逐个应用验证 IPv6，旧系统继续走 IPv4。

它也增加了运维复杂度：NetworkPolicy、Service、DNS、监控和排障都要同时考虑两套地址族。

双栈涉及 API server、controller-manager、kube-proxy、kubelet 和 CNI。实验在 Kind 创建时一次性配置 Pod 与 Service 两组 CIDR。

Kubernetes 双栈功能已经稳定，但现有集群能否在线扩展地址族取决于发行版、网络插件和控制面参数。课程环境直接重建最可靠。

07

Calico 创建两个 IPPool：IPv4 /16 和 IPv6 /48。每个池有自己的 blockSize、封装策略和 NAT 设置。

Service CIDR 不属于 Calico IPAM。Calico 给 Pod 分配地址，Kubernetes 控制面给 Service 分配 ClusterIP。

Different prefix lengths, same block capacity

IPv4 /26 与 IPv6 /122 都包含 64 个地址

IPv4232−26 = 64192.168.x.0/26
=
IPv62128−122 = 64fd00:10:244:...::/122
为什么重要：两种地址族按相近容量向节点分配 block，方便每个 Node 承载相同数量级的 Pod 地址。
08

虽然 /26 和 /122 看起来差很多，但剩余 host bits 都是 6，所以各包含 64 个地址。

IPv6 前缀长度必须结合 128 位地址理解，不能沿用 IPv4 的直觉。

eth1 有一个 IPv4、一个 ULA IPv6 和一个自动生成的 link-local IPv6。

Address scope

global 与 link-local 的使用范围不同

scope global

fd00:10:10::10/64

可以通过路由表跨链路使用，Calico 将其作为 IPv6 Node/VTEP 地址。

routed on eth1
scope link

fe80::.../64

只在当前二层链路有效，用于 Neighbor Discovery 和本地 next-hop。

often needs %interface

IPv6 默认路由经常写成 via fe80::...，因为 next-hop 邻居就在本链路；目标地址仍然可以是 global/ULA。

17

link-local 地址每个 IPv6 接口都有，只在本链路有效。跨链路使用时通常还要指定接口。

Calico 自动探测使用 fd00:10:10::/64 的 global 地址；Pod 默认路由的 next-hop 则可以是 fe80 link-local。

Parallel native paths

外部 v4 与 v6 都走原生三层转发

IPv4
Pod›Node route›eth1›10.10.10.1›1.1.1.1
ip route + ARP
IPv6
Pod›Node route›eth1›fd00:10:10::1›2001:db8::1
ip -6 route + Neighbor Discovery

双栈并不要求两条路径完全相同，但本实验让它们共享同一个 eth1 与 cEOS，同时保留各自的路由表和邻居协议。

25

外部 IPv4 和 IPv6 都从 Node eth1 发出，区别在路由表、网关地址和邻居解析协议。

IPv4 用 ARP，IPv6 用 Neighbor Discovery。观察时分别使用 ip route / ip neigh 和 ip -6 route / ip -6 neigh。

  via fd00:10:244:... dev vxlan-v6.calico
路由职责：它决定“这个目标 block 进入哪个接口”，但还没有决定 outer packet 发往哪台 Node；下一步需要邻居表与 FDB。
29

每个远端节点的 IPv6 Pod block 都有一条 /122 路由，设备是 vxlan-v6.calico。

路由表只把目标交给 tunnel。VXLAN 还要通过 neighbor 和 FDB 找到远端 VTEP。

IPv6 路由里的 next-hop 先通过 Neighbor 表变成 overlay MAC。Calico 安装的是 PERMANENT 项，不依赖广播式学习。

拿到 MAC 后，bridge FDB 才能查出对应的远端 Node IPv6。

route、neighbor、FDB 三张表合在一起，才得到完整的远端转发决定。

Kubernetes service policy semantics

SingleStack、Prefer 与 Require 的失败语义不同

ipFamilyPolicy双栈集群单栈集群适用场景
SingleStack只分配一个地址族正常创建IPv4-only 或 IPv6-only Service
PreferDualStack优先分配两种退化为单栈兼容多种集群能力
RequireDualStack必须分配两种创建失败应用明确要求双栈
Family order：ipFamilies: [IPv4, IPv6] 让 IPv4 成为 primary；交换顺序会改变 legacy clusterIP 的地址族。
35

PreferDualStack 在不支持双栈时可以降级，RequireDualStack 则直接失败。课程使用 Require，能及早暴露集群配置问题。

ipFamilies 的第一项决定 primary family，也是旧 clusterIP 字段展示的地址。

Parallel service proxies

IPv4 与 IPv6 Service 使用各自 NAT 表

IPv4 ClusterIP10.96.x.x:80
iptables nat›Pod IPv4:8080
IPv6 ClusterIP[fd00:10:96::x]:80
ip6tables nat›Pod IPv6:8080
同一 Service，两套规则：EndpointSlice 可以记录两种 addressType，kube-proxy 按地址族编程对应的数据面。
39

IPv4 ClusterIP 通过 IPv4 NAT 规则选择 IPv4 endpoint，IPv6 ClusterIP 通过 IPv6 NAT 规则选择 IPv6 endpoint。

两套规则指向同一逻辑 Service，但地址族不能混用。IPv6 VIP 不会 DNAT 到 IPv4-only endpoint。

双栈不是一条统一路径。目标地址属于 Pod pool、Service CIDR 还是外部范围，会选择不同数据面。

尤其 IPv4 pool 是 CrossSubnet，现场同 subnet 时可能不走 vxlan.calico；IPv6 pool Always 则跨节点固定走 vxlan-v6。
