大家好，这一节我们把跨节点 Pod 流量装进 WireGuard 隧道。应用不需要改代码，仍然发送普通 HTTP；Calico 在源节点加密，在目标节点解密。

验证方法非常直接：开启前 tcpdump 能读到 token 和示例凭据，开启后 eth0 上只看到 Node IP、UDP 51820 和不可读载荷。

主课程：https://k8snetworking.com/lessons/13-wireguard

02

Pod 到 Pod 的逻辑地址属于集群，但跨节点包仍要经过 Node 网卡和 underlay。没有加密时，拥有抓包能力的人可能看到 HTTP header 与 JSON 内容。

本实验故意放入公开的演示字符串来证明风险，不能在真实环境里使用真实密码、token 或云密钥做演示。

03

Calico WireGuard 不是 sidecar，所以不会从 Pod 进程开始一路加密到对端进程。它保护的是 host-to-host 这一段。

源节点收到 Pod 包后加密，目标节点解密后再交给 Pod。同节点通信不会绕到 WireGuard 隧道，这也是实验必须跨节点放置 Pod 的原因。

准确理解：WireGuard 不隐藏外层 Node IP 和 UDP 端口。它隐藏内层 Pod 地址、传输层信息和应用载荷。
04

WireGuard 开启后，underlay 仍要知道把包送到哪个 Node，所以外层 Node IP 和 UDP 51820 是可见的。

真正被加密的是完整内层 IP 包。Pod IP、TCP header、HTTP header 和 JSON 都进入密文载荷。

Node identity and transport sessions

静态身份密钥与会话密钥分工不同

Node A

Static key pair

private A只留在本节点，参与 DH
public A由 Calico 分发给 peers
Noise IKpsk2ephemeral keyssession keys
Node B

Static key pair

private B只留在本节点，参与 DH
public B由 Calico 分发给 peers

准确表述：WireGuard 不使用数字签名来“签出站包”。静态私钥参与 Diffie-Hellman，握手再派生对称会话密钥保护数据包。

20

每个 Node 有长期静态 key pair。私钥留在本节点，公钥提供给 peer。握手还会生成临时密钥，最后派生出数据传输使用的对称 session key。

课程表格写了 private key 用于 sign outgoing traffic，这个说法不精确。WireGuard 协议使用 DH 和 AEAD，不是传统数字签名。

Handshake and transport

握手建立会话，数据包使用对称密钥

Initiatorstatic A + ephemeral a

response
Responderstatic B + ephemeral b
握手输出双向对称 session keys
数据阶段packet counter + AEAD

21

发起方发送 handshake initiation，响应方返回 handshake response。双方用静态和临时 Curve25519 密钥材料派生相同会话状态。

之后每个数据包用高效的对称密钥加密。所谓自动 key rotation，主要指会话密钥通过后续握手更新，不等于每天替换 Node 的静态公钥身份。

WireGuard 不提供大量可选 cipher suite，而是固定 Curve25519、ChaCha20-Poly1305 和 BLAKE2s。

ChaCha20 负责保密，Poly1305 负责认证。没有正确会话密钥的节点既不能读，也不能伪造有效数据包。

NO PLAINTEXT认证通过后
目标节点才能解密

随机外观来自密文，不代表“乱码编码”；没有密钥就无法恢复原始包。

29

即使继续用 -A 输出 payload，也只看到不可读二进制。这里不是换了字符编码，而是原始内层包经过加密。

目标 peer 用会话密钥验证 Poly1305 tag，只有认证成功的包才会解密并交给内层网络栈。

Calico 根据远端节点的 IPAM block 生成前缀路由，Pod 扩缩时不需要为每个地址手工维护一条 tunnel route。

33

课程示例 Table 1 有 192.168.58.192/26 指向 wireguard.cali，backend 的 192.168.58.200 落在这个 block 中。

按 block 路由比逐 Pod 路由更紧凑。现场 block 地址可能不同，结合 calicoctl ipam 和 Pod IP 解释。

Why 0x200000 matters

fwmark 防止外层包再次进入隧道

1inner packetno mark
2WireGuardencrypt + set mark
3outer packet0x200000 → main
没有 mark 会怎样外层 UDP 再次命中 Table 1重复进 wireguard.cali，形成路由环路
34

fwmark 是防环路标记。内层包无 mark，进入 tunnel；外层包由 WireGuard 打 mark，跳过 Table 1。

如果没有这个区分，刚封装好的 UDP 包可能再次被规则送回 wireguard.cali，形成循环。
