外部连接加密到 Gateway，课程后端使用明文 HTTP

大家好，这一节在上一课的 Gateway 和 BGP 入口上加 TLS。重点不是手工生成一张证书，而是看 cert-manager 如何管理完整生命周期，以及 Envoy 如何按 SNI 选择证书。

外部客户端和 Envoy 之间是 HTTPS，Envoy 解密后按 HTTPRoute 转发到集群内的 store、blog 或 api Service。本课后端仍是 HTTP 80，因此这是入口 TLS 终止，不是端到端 mTLS。

主课程：https://k8snetworking.com/lessons/20-ingress-tls

Where encryption ends

TLS 终止发生在 Envoy，后端 Service 继续使用 HTTP

安全边界：TLS 终止保护客户端到 Gateway。若需要 Gateway 到 Pod 也加密，要配置 BackendTLSPolicy、应用 TLS 或服务网格。
02

课程的证书只给 Envoy listener 使用。Envoy 收到 HTTPS、完成握手、解密请求，再发 HTTP 到 backend Service。

所以它保护外部链路，但不自动加密集群内部最后一段。不要把“入口 HTTPS”说成“端到端加密”。

本课没有配置客户端证书验证，因此不是双向 TLS。Certificate 的 client auth usage 也不会自动让 listener 要求客户端证书。

03

TLS 让客户端确认自己连的是受 Lab CA 签发、且 SAN 匹配的服务器，还为后续 HTTP 数据提供加密和完整性。

本课只做服务器认证。清单虽然把 client auth 加进 usage，但 Gateway 没配置 mTLS client validation，所以不会要求客户端证书。

Certificate lifecycle controller

cert-manager 把声明式 Certificate 转换为可消费的 TLS Secret

DESIRED STATECertificate CRdnsNames · duration · issuerRef
reconcile
CONTROLLERcert-managerkey · CSR · issuance · renewal
writes
CONSUMABLEkubernetes.io/tls Secrettls.crt · tls.key · ca.crt

Certificate 是期望状态，Secret 是运行时材料。应用与 Gateway 通常引用 Secret，不直接读取 Certificate CR。

09

Certificate 写域名、签发者、有效期和 Secret 名。cert-manager 负责生成私钥、创建请求、签发和续期，最后把材料写进 Secret。

Gateway 的 certificateRefs 指向 Secret，不是指向 Certificate 对象。

Wildcard

资源少、统一续期，但同一私钥覆盖更多主机。

Dedicated

独立私钥与生命周期，故障和泄露影响范围更小。

18

Wildcard 很适合同一域下大量普通应用，但私钥泄露会影响所有匹配子域。

API 使用独立证书，可以单独轮换、吊销和设置策略，代价是对象更多。

Two issuers, different jobs

SelfSigned 只负责启动 Lab CA，CA issuer 才签发业务证书

selfsigned-issuer

Bootstrap

给 lab-ca Certificate 自签名，生成本地信任根和私钥。

只用于根 CA
lab-ca-issuer

Primary signer

读取 lab-ca-secret 的 CA 私钥，签发 wildcard 与 api 叶子证书。

业务证书入口
生产提示：cert-manager CA issuer 适合实验或有成熟 PKI 运维能力的环境；根 CA 轮换、信任分发和灾难恢复需要单独设计。
19

SelfSigned issuer 不是给每个业务证书直接用，而是用来创建本地 CA。随后 lab-ca-issuer 引用 CA Secret，统一签发叶子证书。

生产本地 CA 管理很复杂，官方也提醒需要专业轮换和信任分发方案。

Bootstrap the trust anchor

lab-ca Certificate 创建十年有效的 ECDSA P-256 本地根 CA

kind: Certificate
metadata:
  name: lab-ca
  namespace: cert-manager
spec:
  isCA: true
  secretName: lab-ca-secret
  commonName: Demo Lab Certificate Authority
  duration: 87600h
  renewBefore: 8760h
  privateKey:
    algorithm: ECDSA
    size: 256
  issuerRef:
    name: selfsigned-issuer
    kind: ClusterIssuer
24

lab-ca 的私钥由 cert-manager 生成，Certificate 标记 isCA true，再由 selfsigned issuer 用同一把私钥签署自己的 CA 证书。

这个 CA 有十年有效期，Secret 包含 CA 私钥。实验方便，生产需要更严格的密钥保护。

Choose based on ownership

Wildcard 减少对象数量，Dedicated 缩小密钥影响范围

Distribute the trust anchor

Changing signer changes client trust

修改 issuerRef 会触发重签发，但同时改变信任链

BEFORElab-ca-issuertrusted by /tmp/lab-ca.crt
patch issuerRef
AFTERselfsigned-issuernew self-signed leaf
$ kubectl patch certificate api-demo-lab -n cert-manager-demo --type='json' -p='[
  {"op":"replace","path":"/spec/issuerRef/name","value":"selfsigned-issuer"}
]'

旧 Lab CA 不会信任新的 self-signed leaf。切换 Issuer 前必须先规划 trust bundle 过渡，实验后应恢复原 issuer。

57

修改 issuerRef 本身会触发重签发，不一定需要删除 Secret。切到 selfsigned 后，新证书不再由 Lab CA 签，客户端现有 CAfile 会验证失败。

生产 Issuer 迁移必须先分发新信任链，并安排重叠窗口。
