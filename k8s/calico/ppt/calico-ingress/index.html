02

Gateway API 是规范，不是代理进程。Envoy Gateway 是控制面实现，真正收发流量的是 Envoy Proxy。

Calico 通过 Operator 把这些组件安装和管理起来，再把 LoadBalancer IPAM 与 BGP 宣告接进外部网络。

httproute.yaml

HTTPRoute 匹配 Host 与路径，并给两个 Service 设置权重

kind: HTTPRoute
metadata:
  name: canary-traffic-split
  namespace: default
spec:
  hostnames: ["app.demo.lab"]
  parentRefs:
  - name: calico-ingress-gateway
  rules:
  - matches:
    - path: {type: PathPrefix, value: /}
    backendRefs:
    - name: app-v1
      namespace: ingress-gateway-demo
      port: 80
      weight: 80
    - name: app-v2
      namespace: ingress-gateway-demo
      port: 80
      weight: 20
27

HTTPRoute 先通过 parentRefs 附加到 Gateway，再匹配 Host app.demo.lab 和所有以 / 开头的 path。

backendRefs 指向另一个 namespace 的两个 Service，因此依赖刚才的 ReferenceGrant。

app.demo.lab 由 HTTPRoute 匹配，不在 Gateway listener 上

Weighted routing semantics

80 与 20 是相对权重，不是固定请求编号规则

app-v1weight 80

长期期望约 80%。

app-v2weight 20

长期期望约 20%。

不是：前 80 个请求固定去 v1，后 20 个固定去 v2。

也不是：每 5 个请求必然 4 个 v1、1 个 v2。

应理解为：每次选择按权重参与，样本越大越接近配置比例。

39

权重是相对数，80:20 与 8:2 在比例上等价。实现会根据连接和请求进行选择。

小样本出现偏差很正常，测试时至少做几十到几百次，并看多个时间窗口。
