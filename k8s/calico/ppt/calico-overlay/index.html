大家好，这一节我们来看 Calico Overlay。实验里有四个 Kind 节点，前三个在 10.10.10.0/24，worker3 在 10.10.20.0/24，中间由 Arista cEOS 做三层转发。

我们重点观察一个选择题：目的节点和源节点在同一个子网时，Calico 直接路由；跨子网时，Calico 才通过 vxlan.calico 封装。这就是 VXLANCrossSubnet。

课程：Lesson 06 Calico Overlay Networks

Why an overlay exists

Overlay 解决 underlay 不认识 Pod CIDR 的问题

没有 Overlay

192.168.209.64/26 ?

underlay 路由器需要知道每个节点后的 Pod CIDR，否则它无法把原始 Pod 包送到目标节点。

使用 VXLAN

10.10.10.11 → 10.10.20.20

underlay 只转发节点 IP。Pod 包藏在 VXLAN 外层，目标节点解封装后再交给 Pod。

CrossSubnet 只在跨越子网边界时封装，减少同子网流量的额外开销。

02

Overlay 的价值不是让包凭空消失，而是把 underlay 不认识的 Pod 地址藏起来。交换机和路由器只需要认识 10.10.10.11 与 10.10.20.20 这样的节点地址。

Calico 官方也建议在可以直连时尽量避免无必要的封装。CrossSubnet 正好折中：同一二层域直接转发，跨路由边界再封装。

Calico 官方：Overlay networking

03

CrossSubnet 的核心判断发生在节点侧。Felix 根据节点地址和 IPPool 模式安装不同的路由。同子网的目标 block 指向远端节点的 underlay IP，跨子网的目标 block 指向远端 VTEP。

所以排错时不要先猜 VXLAN。先看路由表选了 eth1 还是 vxlan.calico，选择结果已经告诉我们接下来应该检查哪条路径。

calico-cni-config/custom-resources.yaml

Installation 资源定义 VXLAN CrossSubnet

calicoNetwork:
  ipPools:
  - name: default-ipv4-ippool
    blockSize: 26
    cidr: 192.168.0.0/16
    encapsulation: VXLANCrossSubnet
    natOutgoing: Enabled
    nodeSelector: all()
    disableBGPExport: true
  nodeAddressAutodetectionV4:
    cidrs:
    - 10.10.0.0/16

VXLANCrossSubnet

只封装跨节点子网流量。

blockSize: 26

Calico IPAM 按 /26 block 分给节点。

地址自动检测

只从 10.10.0.0/16 选择节点地址。

同一清单还创建 APIServer、Goldmane 和 Whisker；Overlay 数据面参数集中在 Installation.spec.calicoNetwork。

13

这一段是整个实验的关键配置。Operator 会根据 Installation 创建实际的 default-ipv4-ippool。

natOutgoing 用于 Pod 访问 IPPool 外部地址时做源 NAT，不是 Pod 跨节点 VXLAN 成立的条件。disableBGPExport 表示不要把该池路由导出给 BGP，它也不等于“关闭所有 Calico 路由编程”。

Encapsulation and encryption

Calico 数据面选项的职责不同

选项主要作用underlay 要求典型开销
None保留原始 Pod IP 路由underlay 必须学习 Pod 路由最低
IP-in-IPIPv4 包套在 IPv4 包中允许 IP 协议 4约 20B
VXLAN二层帧套入 UDP 隧道节点间允许 UDP 4789IPv4 常见约 50B
WireGuard加密节点间工作负载流量允许 UDP 51820/51821取决于协议族

术语修正：WireGuard 主要提供加密，可以与路由或封装方案组合使用，不应简单归类为 VXLAN/IP-in-IP 同类的封装模式。

17

课程列出了 IP-in-IP、VXLAN、None 和 WireGuard。为了术语准确，这里把它们称为数据面选项，而不是都叫封装类型。

VXLAN 和 IP-in-IP解决 underlay 不认识 Pod 路由的问题。WireGuard主要解决传输加密，它可以叠加在 Calico 的节点间通信之上。

vxlan.calico 是节点上的 VTEP 接口

VTEP 地址

课程示例使用本节点 IPAM block 的首地址 /32。

接口 MAC

neighbor 表把远端 VTEP IP 映射到远端 VXLAN MAC。

MTU 1450

为 IPv4 VXLAN 外层预留约 50 字节。

23

vxlan.calico 是 Linux 内核的 VXLAN 设备，也是 VTEP。它的 /32 地址通常与本节点 block 的网关地址对应。

state UNKNOWN 对这类虚拟接口很常见，不能单凭 UNKNOWN 判断故障。更重要的是接口要 UP、LOWER_UP，并且路由、neighbor 和 FDB 条目完整。

外层目的地址是 worker3 的 Node IP，内层目的地址始终是 Pod B。解封装不会改变原始 Pod 五元组。

源 Pod 包到 worker 后进入 vxlan.calico。内核根据 neighbor 和 FDB 找到远端 VTEP，添加外层 Ethernet、IP、UDP 与 VXLAN 头。

cEOS 只按 10.10.20.20 转发外层包。worker3 收到 UDP 4789 后解封装，恢复原始 Pod 包，再根据本地 cali 路由交给目标 Pod。

MTU 错误的表现

28

VXLAN 把原始二层帧包在 VXLAN、UDP、外层 IP 和外层 Ethernet 后面。IPv4 常见增加约 50 字节，因此课程里的 vxlan.calico MTU 是 1450。

这是常见值，不是所有环境的固定答案。Calico 会根据启用的封装和节点 MTU 自动检测，云平台或嵌套隧道可能需要更小值。

Calico 官方：Configure MTU

Linux forwarding chain

VXLAN 转发需要路由、Neighbor 与 FDB

01RoutePod CIDR → remote VTEP
02NeighborVTEP IP → VXLAN MAC
03Bridge FDBVXLAN MAC → Node IP
04Underlay routeNode IP → gateway / eth1

Calico/Felix 预编程这些静态条目，内核无需广播 ARP 或通过动态 MAC 学习寻找远端 VTEP。

29

课程把 VXLAN 转发拆成四次查找。先由路由表决定远端 VTEP，再由 neighbor 把 VTEP IP 映射到隧道 MAC，FDB 把该 MAC 映射到远端 Node IP，最后 underlay 路由外层 Node IP。

neighbor 和 FDB 中的 PERMANENT 表示由控制面安装，而不是靠数据面广播学习。任意一个映射缺失，都可能导致跨子网失败。

ip neighbor show

30

这张表回答的是：如果下一跳是 192.168.81.64，在 vxlan.calico 上应该构造哪个目标 MAC。

它还没有告诉内核外层 IP 应该发给哪个节点。那一步要继续查 bridge FDB，把这个 VXLAN MAC 解析成远端 underlay IP。

bridge fdb show

Bridge FDB 把 VXLAN MAC 指向远端 Node IP

# bridge fdb show | grep 66:fb:ad:98:aa:13

66:fb:ad:98:aa:13 dev vxlan.calico dst 10.10.10.11 self permanent
Inner destination MAC66:fb:ad:98:aa:13
Remote VTEP underlay IP10.10.10.11
Outer UDP packetdst port 4789

Neighbor 与 FDB 配合完成两次映射：VTEP IP → VTEP MAC → Node underlay IP。

31

FDB 的 dst 字段是远端节点 underlay IP。内核会把 VXLAN UDP 包发往 10.10.10.11，而不是把 192.168.81.64 直接交给物理网络。

排错时要用同一个 MAC 串起 neighbor 和 FDB。只看任意一张表，很容易漏掉中间映射不一致的问题。

Evidence on both interfaces

同子网测试时，eth1 上应看到原始 Pod IP，而不是 UDP 4789。跨子网测试才应看到 VXLAN。

32

抓包最好同时开两个窗口。vxlan.calico 展示隧道设备处理的内层流量，eth1 展示真正离开节点的外层 UDP 4789。

如果 vxlan.calico 有包但 eth1 没有，重点看 neighbor、FDB 和主机防火墙。如果 eth1 发出但对端收不到，继续检查 cEOS 路由、VLAN 和 UDP 4789 可达性。

33

Overlay 排错也沿路径找第一个缺失事实。节点地址不对时，不要直接看 FDB；路由没有选择 vxlan.calico 时，也不应该期待 UDP 4789。

同子网和跨子网分别测试很重要。只有跨子网失败，范围就可以快速收敛到 VTEP、UDP 4789、三层 underlay 或 MTU。

35

最后用三句话收尾。第一，underlay 必须先让 Node IP 可达。第二，CrossSubnet 通过节点子网判断选择直连或 VXLAN。第三，跨子网转发依靠 route、neighbor 和 FDB 共同建立远端 VTEP 映射。

看到跨子网故障时，从这条证据链逐项验证，比直接重启 calico-node 更快定位真正的断点。
