02

动态和静态并不是两套网络。它们都走 Calico CNI、IPAM 和同一份 Pod 路由。

差别只在谁选择地址。动态由 IPAM 算法选，静态由 annotation 提出具体地址，IPAM 再检查能否分配。

Use sparingly

只有地址本身有外部契约时才考虑静态 IP

ACL

遗留系统白名单

对方只能按单个源地址授权，短期无法改造。

DNS

外部记录直指 Pod

某些设备或集成要求固定目标 IP。

OBS

明确实例识别

日志、探针或抓包按固定地址关联设备。

STATE

特殊有状态协议

成员协议把地址当作持久身份的一部分。

默认建议：普通应用优先使用 Service、Headless Service 或 StatefulSet DNS。把 Pod IP 暴露为长期契约会增加调度、扩缩和故障恢复成本。

03

静态 Pod IP 是兼容性工具，不是通用最佳实践。外部系统真的把 IP 当契约时才值得使用。

能用 Service 或 StatefulSet 稳定 DNS 解决的场景，通常不要把单个 Pod IP 暴露出去。

Three different identities

稳定 Service、稳定 DNS 与静态 Pod IP 不是一回事

机制稳定对象后端变化主要用途
ClusterIP Service虚拟入口 IP / DNS可任意替换 Pod普通服务发现与负载均衡
StatefulSet + HeadlessPod DNS ordinalPod IP 可变化稳定成员名称
Static Pod IP请求的 Pod 地址必须重新请求同一 IP外部 IP 契约
关键区别：静态 IP 不会自动让 Deployment 的所有替代副本继承同一个地址，也不会提供负载均衡或健康检查。
04

ClusterIP 稳定的是入口，StatefulSet 稳定的是名称，静态 IP 稳定的是一次明确请求的地址。

选择机制时先问外部依赖真正需要什么，不要把所有“稳定身份”混成同一问题。

Reservations are checked at allocation time

预留必须早于自动分配才有保护作用

正确顺序
create reservation›create dynamic pods

allocator 从一开始就跳过 reserved range。

错误假设
IP already allocated›create reservation

reservation 不会自动撤销已有 allocation。

IPReservation 每次自动分配时被查询。它不是后台回收控制器，也不会主动迁移已经运行的 Pod。

13

Reservation 要在动态工作负载大量创建前应用。地址已经分配后再 reserve，不会让现有 Pod 释放它。

这也是 deploy.sh 先创建 reservation、再创建 dynamic-pod 的原因。

Keep the reserved fraction small

IPReservation 适合保留小范围地址

本实验8 / 65,536

在 /16 中预留一个 /29，搜索影响可以忽略。

大比例预留> 10%

官方文档提醒：allocator 搜索空闲 block 可能明显变慢。

资源数量少量对象

把多个 CIDR 放进一两个 IPReservation，避免创建大量小对象。

大量手工地址时：考虑创建专用 IPPool，并用 nodeSelector: "!all()" 禁止自动分配整个池。
14

IPReservation 为少量地址设计。预留池中很大比例会让自动分配频繁跳过不可用区间。

如果业务需要成百上千个手工地址，专用手工 IPPool 比一大堆 reservation 更清晰。

18

annotation 的值不是 YAML list，而是包含 JSON array 的字符串。用单引号包住外层可以减少转义。

课程原始清单使用双引号外层和转义双引号，语义相同。格式错了会在 CNI 阶段解析失败。

Annotation contract

格式、优先级与地址数量都有明确限制

规则含义常见错误
JSON array string'["192.168.100.10"]'写成普通逗号字符串
每地址族最多一个一个 IPv4，或一个 IPv6，或各一个请求两个 IPv4
ipAddrs 优先与 ipv4pools/ipv6pools 同时存在时，具体地址优先以为 pool annotation 会覆盖
创建时读取Pod sandbox 创建前必须存在运行后再 annotate
19

当前官方文档限制每个 Pod 每地址族最多一个具体地址。双栈可以同时申请一个 v4 和一个 v6。

具体 ipAddrs 比 pool selector 更精确，因此同时配置时它优先。

Kubelet to IPAM

失败位置：地址冲突或池外地址会让 CNI ADD 失败，容器尚未真正启动，因此 Pod 常停在 ContainerCreating。
20

Pod 对象先写进 API，kubelet 创建 sandbox 时调用 CNI。Calico CNI 读取 annotation，再请求 IPAM。

只有 IPAM 成功并配置网络后，容器才启动。因此重复 IP 不是应用启动失败，而是 sandbox 网络创建失败。

What persists and what does not

静态 IP 是可重复申请，不是永久租约

保持

YAML 中的 IP 请求

控制器每次创建 Pod template 都携带相同 annotation。

变化

Pod UID 与 IPAM handle

每次删除重建产生新对象和新的 allocation owner。

new Pod, new handle

删除到重建之间，地址处于 free 状态。Reservation 防止自动分配抢走它，但另一个显式静态请求仍可能申请它。

34

“静态 IP 持久”容易让人误以为地址永远绑定 Pod 名。实际持久的是部署清单中的请求。

Reservation 只挡自动分配。另一个有权限写 ipAddrs 的用户仍可在窗口期申请 .10，所以需要准入控制和变更流程。

Choose the reservation boundary

少量地址用 Reservation，大段地址用专用 Pool

方案配置适合规模特点
IPReservation在现有 pool 中列 reservedCIDRs少量 IP / 小 CIDR动态 allocator 跳过，手工仍可用
Manual-only IPPoolnodeSelector: "!all()"完整地址段整个 pool 不自动分配
Topology pool按 Node/区域 selector 分池按拓扑管理限制哪些 Node 可使用
共同要求：静态请求仍必须落在配置 IPPool 内，且当前没有其他 endpoint 占用。
37

少量地址嵌在大 pool 中，Reservation 最方便。整段都用于手工分配时，用 !all() 的专用 pool 更清晰。

如果还要按 rack、namespace 或 Node 管理，则结合多 IPPool 和 selector。

IPv6fd00:10:244::10

必须位于 IPv6 IPPool。

38

在双栈集群中数组可以包含一个 IPv4 和一个 IPv6。两者分别由对应 IPPool 校验。

不能用这个 annotation 给同一 Pod 请求两个 IPv4。多接口或多地址需求要看 Multus 等其他方案。

A different, disabled-by-default feature

ipAddrsNoIpam 会绕过冲突与分配管理

ipAddrs

Calico IPAM 管理

检查 pool、冲突、allocation、释放与 owner。

本课程使用
ipAddrsNoIpam

绕过 IPAM

冲突和路由交给其他系统，默认关闭，还可能扩大 IP spoofing 风险。

本课程不使用

39

ipAddrsNoIpam 名字很像，但语义完全不同。它不在 IPAM 建 allocation，因此 Calico不能替你防重复。

除非有外部 IPAM、路由系统和准入控制，否则不要开启。

副本限制：同一个 template 中写单个静态 IP 时，replicas 必须为 1。扩到 2 个副本会让第二个 Pod 与第一个冲突。

生产通常由控制器重建 Pod，所以 annotation 要放 template。手工 Pod 删除后不会自动回来。

Operational costs

静态 Pod IP 把调度问题变成地址协调问题

01

并发重建

旧 Pod 尚未释放时，新 Pod 请求同一 IP 会失败。

02

扩缩容

一个 template 不能让多个副本共享同一静态地址。

03

权限

有权写 ipAddrs 的租户可抢占预留地址。

04

外部依赖

IP 白名单、DNS 与监控都要同步生命周期。

为关键静态地址建立唯一 owner、准入校验、变更审批和冲突告警。Reservation 本身不表达“谁有权申请”。

41

静态 IP 减少地址变化，却增加生命周期协调。rolling update 若先启动新 Pod，再删除旧 Pod，就会冲突。

还要控制谁能写 annotation。Reservation 防自动分配，不是授权系统。
