大家好，这一节讲选择性 BGP Peering。五台 Kubernetes Node 都物理连接 ToR，但只有 worker 和 worker2 建立 BGP 会话。

02

如果集群 500 台 Node 全部直连 ToR，就要维护 500 个外部 BGP session。ToR 的 CPU、内存和 peer 配额都会承压。

课程提到常见设备可能只有几十到一百多个 peer 容量，具体数字取决于型号和软件版本，生产设计要查设备规格。

标签属于 Kubernetes Node metadata；Calico selector 根据标签持续计算应建立哪些 BGP session。

08

Kind 清单在 worker 和 worker2 上预置 bgp-peer=true。其他三台 Node 没有这个标签。

标签不是一次性生成配置。Calico持续 watch Node metadata，后续加减标签会动态建立或拆除 session。

13

peerIP 和 asNumber 定义远端 cEOS，nodeSelector 定义哪些本地 Calico Node 应建立会话。

selector 每命中一台 Node，就生成一条到 10.10.10.1 AS65001 的 peering。

Peer scope changes with one field

省略 nodeSelector 会变成全局 Peer

Global peer

省略 node 与 nodeSelector

集群中所有 Calico Node 都尝试与 peerIP 建立会话。

5 nodes → 5 sessions
Node selector peer

nodeSelector: bgp-peer == "true"

只有带匹配标签的 Node 建立会话。

5 nodes → 2 sessions

nodeSelector 与单个 node 字段是两种互斥作用域；peerSelector 则用于选择远端 Calico Node，不用于本课的固定 ToR IP。

14

BGPPeer 没有 node/nodeSelector 时是 global scope，所有 Node 都会尝试连接。加 nodeSelector 后变为节点选择范围。

peerSelector 是另一种模式，用标签选远端 Calico Node；本课远端是固定 cEOS，所以使用 peerIP。

一台 speaker 故障后，BGP 检测 session down，撤销它的 path。cEOS 只保留另一条 next hop。
