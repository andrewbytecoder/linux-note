## About Calico eBPF
虽然 Linux 内核在构建网络、可观测性以及安全性功能方面非常强大，但长期以来，它也给开发者带来了不少挑战。比如添加内核模块或修改内核源代码这类任务，往往涉及到复杂的抽象概念和复杂的系统结构，这使得调试工作变得困难。而扩展的 Berkeley Packet Filter（eBPF）则提供了一种解决这些问题的方案。
eBPF 是一种内核技术，自 Linux 内核版本 4.4 起就完全集成到内核中。它使得程序可以在不需要外部内核模块或修改内核源代码的情况下运行。可以将其视为一种轻量级、封装在 Linux 内核内部的虚拟机器。这使得开发者能够运行利用特定内核资源的字节码程序。
通过使用 eBPF 技术，就无需修改内核源代码了，同时软件能够更方便地利用现有的内核层功能。因此，这项技术有潜力从根本上改变诸如可观测性、安全性和网络相关服务等关键服务的提供方式。

### Architecture overview
Calico 的 eBPF 数据平面将 eBPF 程序绑定到了每个 Calico 接口的 `tc` 钩子中，同时也会应用于数据接口和隧道接口。这样，Calico 能够更早地检测到工作负载中的数据包，并通过一条快速路径来处理这些数据包，从而绕过内核通常使用的 iptables 和其他数据包处理机制

![[PixPin_2026-09-09_20-42-51.png]]

实现负载均衡和数据包解析的逻辑是提前预编译好的，它依赖于一组 BPF 映射来存储 NAT 前端和后端的信息。其中一个映射存储了服务的元数据，从而能够支持“粘性”服务。另一个映射则存储了支持后台 Pod 的 IP 地址。

在 eBPF 模式下，Calico 会将您的策略转换为优化的 eBPF 字节码。为了实现这一功能，Calico 会使用 BPF 映射来存储由策略选择器匹配到的 IP 地址集。

![[PixPin_2026-09-09_20-44-15.png]]

为了提升服务的性能，Calico 还通过介入套接字的 BPF 钩子来实现连接时的负载均衡。当程序尝试连接到 Kubernetes 服务时，Calico 会拦截该连接请求，并配置套接字直接连接到后端节点的 IP 地址。这样就能消除服务连接过程中的 NAT 开销。
